# AI 本地预览无法打开：复现与修复

日期：2026-10-23。用户报告之前提供的本地预览打不开。

## 原因与证据

原链接为 `http://127.0.0.1:4191/dist/toy/index.html`。系统HTTP请求连接被拒，实际Chromium报告 `net::ERR_CONNECTION_REFUSED`；4191没有监听服务。`dist/toy/index.html` 和双端构建仍在，故障发生在本地预览进程可用性这一层。此前服务依赖开发时启动的临时进程，退出后链接失效；旧 `npm run dev` 默认端口4173又与所提供4191链接不同。

## 修复

- `npm run dev` 改用AI专属启动器，默认4191；启动时重新构建，未收到真实名单时明确使用开发fixture，不更改正式构建规则。已有单份真实名单时提示补齐，避免掩盖部分输入。
- 增加 `npm run preview:start` 和根目录 `启动AI预览.cmd`。独立Node后台进程把输出写入 `output/ai-preview-*.log`，启动器退出后服务仍运行；双击CMD还会打开浏览器。未增加系统开机启动或后台计划任务。
- 服务启动后检查应用ID及实际工作目录；重复启动复用同项目进程，其他项目占用端口时报明确错误，不终止或替换它。
- 新增健康检查、入口缺失503提示、资源MIME、禁止缓存及构建目录边界检查。保留原完整链接，同时支持根入口和 `/toy`、`/xhs`。
- 对简短入口使用302跳转到真实HTML路径，保证 `./core.js`、`./style.css` 等相对资源解析正确。调试新入口时曾复现资源403/MIME错误，已在交付前修复并添加回归。

只变更开发预览工具、npm入口及文档；没有修改产品运行代码、草稿键、真实名单或发行ZIP，也没有上传平台。

## 验证

1. `npm test` 在允许本机回环连接的系统环境运行：**31项通过**，其中8项为新增预览服务测试，覆盖默认端口、跳转与原链接、资源MIME/no-store、缺构建提示、目录边界、坏URL、不支持方法、健康检查、同项目重复启动、异项目占用和错误端口。受限沙箱最初出现 `connect EACCES`，在实际系统环境重跑后通过，未把权限错误当成服务逻辑通过。
2. `scripts/browser-ai-preview.js`：**23项通过**，覆盖根入口、`/toy`、旧完整链接、`/xhs`，逐个确认HTTP200、规范路径、脚本初始化及默认App榜；检查LLM切换、自定义条目排名与刷新恢复、1张直接清空、320/1440布局。零脚本异常、零失败资源。
3. 在启动器已退出的后续独立命令与浏览器会话中仍能连接后台服务。再次启动复用同一PID，证明不需要保持启动器终端运行。
4. `node scripts/ai-check.mjs` 两端通过：13个文件，Toy解压89,595字节、小红书90,917字节，产物哈希与原构建清单一致，ES2017解析通过。

浏览器为Chromium `155.0.8059.86`。日志：`output/ai-preview-browser-2026-10-23.log`；截图：`output/playwright/ai-preview-open-fixed.png`。

## 使用

双击 `启动AI预览.cmd`；或在项目根运行 `npm run preview:start`。

- [本机浏览器版预览](http://127.0.0.1:4191/)
- [本机小红书页面预览](http://127.0.0.1:4191/xhs)

此地址为本机服务，电脑重启后需重新启动；当前仍是虚构示例名单，并非线上Toy作品或小红书真实宿主。正式名单、真机验证和线上发布不属于本轮修改。
